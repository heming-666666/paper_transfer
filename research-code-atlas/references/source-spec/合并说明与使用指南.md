## 1. 合并取舍

### 1.1 最大分歧：底座选哪个

| | Codex 方案 | Claude 方案 | 最终 |
| --- | --- | --- | --- |
| 底座 | 改造 Understand-Anything（TS/React/pnpm，Zod schema，sidecar） | 自建：Python `ast` + 原生 JS 页面 + 本地 Cytoscape.js | **自建** |
| 理由 | 复用成熟面板与解析器 | 本地模型弱，改 React 工程 + workspace 构建失败率高；上游 CodeViewer 靠本地接口读源码，离线双击不可用 | 弱模型能完成、离线可用、出错易定位 |
| Understand-Anything 的角色 | 运行依赖 | 设计参考 | 设计参考 + “以后可选”导出兼容图 |

### 1.2 从 Codex 版吸收的（Claude 草案没写或写得不够）

- 六种证据状态，并且**每个结论单独标**，不是整张卡片只有一个标签。
- 稳定符号 ID 规则、多入口 `scenario_contracts`（同一函数在 train/eval 下契约不同、互不覆盖）。
- IO 字段对象（container_path / shape / dimensions / reason）和“shape 不靠猜”的查证顺序。
- 论文映射表字段（相比什么改变 / 修改约束 / direct·inferred·not_found·conflict）、公式与代码冲突的处理。
- 实验设置“论文值 / 默认值 / 最终值 / 消费行”三方对照与优先级。
- 源码快照 + 新鲜度（未重验 / matched / stale / unknown）、`--recheck-source`。
- CLI 退出码 0/1/2/3、HTML 安全（`</script>` 注入、禁止 innerHTML）、127.0.0.1 绑定。
- PyTorch 语义区分（调用图 ≠ 模块树 ≠ 数据流 ≠ 反向图）。
- 可选 runtime 观测的边界、工作区规则（Capture → Check、Claude 迁移待办）、“不算完成”清单。

### 1.3 Claude 版新增的（专门针对弱模型）

- **本机实测事实**：默认 `python` 是 3.8 不能用 → 用 `py -3.13`；PyYAML/PyMuPDF 未装；`pdftotext` 可用；Claude Code 的 skill 目录实际在 `D:\APP\ClaudeCode\config\skills\`（因为设置了 `CLAUDE_CONFIG_DIR`），放在 `~/.claude/skills` 不会被发现。
- **脚本出骨架、agent 只填空**：脚本自动生成每个函数的步骤骨架（带行号）和 shape 线索，agent 不能改行号，从根上减少行号幻觉。
- **防编造的自动核对**：agent 只写 `"文件:起-止"`，脚本校验并算哈希；论文引文必须能在对应 PDF 页文本中找到，否则 check 报错。
- **可直接照抄的代码骨架**：AST 作用域遍历（嵌套函数、装饰器/默认值定义时执行、条件栈）、调用解析的逐条规则、前端 hash 路由/源码高亮/层级树/Cytoscape 初始化。都已用 Python `ast.parse` 和 `node --check` 做过语法检查。
- **完整 fixture + 19 条 ground truth 边**：同名函数、别名、相对导入、self 属性推断、递归、动态调用、装饰器、两个入口共享函数、`</script>` 注入、测试论文（direct/conflict/not_found、mismatch/defined_not_consumed 都覆盖）。
- **双击即可打开**：数据用 `<script src="atlas-data.js">` 加载，`file://` 下直接可用，不必开服务。
- **调用层级树**（纯 HTML，递归处显示 ↻），图库没装时也能用。
- 每阶段写明“做什么 → 用什么 → 产出 → 验收命令 → 通过标准”，以及“同一错误失败 2 次就停下诊断”。
- 补充核验过的现成 skill：walkthrough、showme-skill、codebase-to-course、paper-to-course、claude-paper、graphify。

## 3. 怎么用

### 第一步：让本地 agent 创建 skill

在 `D:\Code` 打开本地 agent（Claude Code 或 Codex 都可以），发送：

```text
读取 D:/Code/research-code-atlas-skill/prompt_final.md 全文，严格按其中的阶段 0–9 实际创建并验收 research-code-atlas skill。
建设目录 D:/Code/tools/research-code-atlas。不要修改 D:/Code/research-code-atlas-skill/ 里的任何文件和 D:/Code/prompt.md。
每个阶段结束把验收命令、退出码、结果写进 HANDOFF.md 再继续。需要授权的事一次性列给我。
```

如果你愿意一次性授权，可以紧接着补一句（按需删改）：

```text
授权：在 D:/Code/tools/research-code-atlas/.venv 用 py -3.13 建虚拟环境并安装 pyyaml；
用 npm pack 下载 cytoscape@3.34.3 和 cytoscape-dagre@4.0.1 只取 dist 文件放进 skill 的 assets/viewer/vendor；
验收通过后把 skill 复制到 D:/APP/ClaudeCode/config/skills/research-code-atlas（已存在就先对比，不要覆盖）。
不要全局改 Python/Node，不要下载模型或数据集，不要运行任何被分析项目。
```

上下文用完中断时，新会话里说：“继续 D:/Code/tools/research-code-atlas/HANDOFF.md 里的任务，按 prompt_final.md 的下一阶段执行。”

### 第二步：确认它真的做完了

对照 `prompt_final.md` 第 19、20 节，至少看到：
- `tests` 的 ground truth 测试全部通过（让它把 unittest 输出贴出来）；
- fixture 的 `viewer/index.html` 能双击打开，点 `losses.normalize` 和 `helpers.normalize` 跳到不同文件，`fact` 递归显示 ↻；
- 新会话中 `/research-code-atlas`（Claude Code）或 `$research-code-atlas`（Codex）可见。

只有 SKILL.md、只有截图、只有 `--help` 能跑，都不算完成。

### 第三步：日常使用

```text
/research-code-atlas
项目：D:/Research/MyProject
入口：train.py（train）
论文：D:/Papers/my-paper.pdf
配置：configs/train.yaml；启动参数：--config configs/train.yaml
重点：训练主循环、forward、loss、论文创新模块、关键实验设置。只做静态分析。
```

更多写法（多入口对照、准备修改、源码改过后重验）见 `prompt_final.md` 第 21 节。

### 第四步：在界面里学习的推荐顺序

1. **总览**：入口一句话作用 + 阶段（配置→数据→模型→loss→更新→评估）+ 一个样本的数据流（shape 变化）。
2. **调用层级**：从入口逐层展开，注意每行的调用条件（if/for）。
3. 点**核心函数** → 右侧卡片看用途、输入输出、副作用 → 中间**内部流程**逐步点击对照源码。
4. **论文对照**：从创新点跳到实现函数，看“论文步骤 ↔ 代码步骤”，留意 conflict / not_found。
5. **实验设置**：看论文值和代码默认值哪里不一致、在哪一行被使用。
6. 准备改代码时选中目标函数 → **修改影响**：上游调用者、下游消费者、相关配置/loss/论文约束 → 再让 agent 写针对性的 change-impacts。
7. **未知清单**：未解析的动态调用（如 `model(batch)`）是静态分析看不到的地方，必要时自己顺着源码确认，或授权一次小样例运行观测。

## 4. 已知限制

- 只深度支持 Python；其他语言只列文件。
- 动态调用、注册表、参数传入的 callable 静态无法确定，会标“未解析/候选”。
- shape 大多是“推断”，只有注解、assert、collate 等有证据时才是“源码确认”。
- 扫描版 PDF 没有文本层时，论文引文核对会失败，需要人工看原页（按要求不装 OCR）。
- 本文件和 `prompt_final.md` 都只是任务说明；skill 本身还没有创建、安装或运行过。
