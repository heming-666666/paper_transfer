# 代码与论文执行逻辑可视化 Skill：调研依据

检索日期：2026-10-12（北京时间）。本文件记录实际检索与官方资料核验；没有在本机安装或运行以下候选项目。仓库维护信息是检索时快照，不能代表永久状态。正文中的推荐是需求匹配判断，不是上游已经实现论文对照功能的证明。

## 1. 推荐方向

**推荐：基于 Understand-Anything 改造，封装 `research-code-atlas` skill。** 复用其结构提取、图谱数据类型、搜索、图浏览与源码组件，添加入口范围、函数输入输出、控制流程、论文证据、实验差异和修改影响。不要同时安装数个图谱后端，不要先开发新的跨语言解析框架。

最小完整交付：Python 研究代码的入口链路分析、中文函数卡片、可点击的本地网页、论文与实验对照，以及明确的不确定性。运行追踪为增强模式；静态模式不需要目标项目能运行，也不需要 GPU、权重或完整数据集。

Understand-Anything 已有可视化图谱和多种代码理解 skills；上游面向通用项目理解，您要求的逐函数数据契约、论文创新定位与实验参数三方对照需要增加专门的数据结构与验收。依据：[官方 README](https://github.com/Egonex-AI/Understand-Anything)、[图谱类型](https://github.com/Egonex-AI/Understand-Anything/blob/main/understand-anything-plugin/packages/core/src/types.ts)。

## 6. 精度与实现依据

- Python [ast 官方文档](https://docs.python.org/3/library/ast.html)：适合补充参数、默认值、返回、调用位置和控制结构；语法树不等于完整类型推导或运行轨迹。
- Python [sys.setprofile 官方文档](https://docs.python.org/3/library/sys.html#sys.setprofile)：可用于已授权样例的调用观测；线程、进程、异步、原生扩展及局部变量获取必须单独处理。
- [OpenAI 当前 Skill 文档](https://learn.chatgpt.com/docs/build-skills)：保持入口简明，把复杂流程与 schema 放到 references；实际发现性需通过目标客户端验证。
- [Understand-Anything 已知提取缺口](https://github.com/Egonex-AI/Understand-Anything/issues/692)：静态解析支持某种语言，不代表每个框架与导入路径都能完全解析。

独立技术审查补充了：动态分派不确定边、PyTorch 模块调用语义、张量格式证据、配置覆盖优先级、论文代码冲突、内置源码快照、HTML 文本安全与真实项目验收。相关要求已纳入 `prompt.md`。
